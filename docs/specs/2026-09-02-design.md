## 1. Visão

TokenBar é um app **nativo macOS, open source**, que vive na menu bar e mostra, em tempo real, o uso e os limites das assinaturas e APIs de IA do usuário: Claude Code, Codex/OpenAI, Gemini CLI, Z.ai, Cursor, OpenRouter e outros. É a resposta direta ao CodexBar (referência do produto), com duas promessas que ele não cumpre:

1. **Leveza verificável** — CPU ociosa < 0,5% sustentado, teto de ~40 MB de RAM, zero rede em sleep, re-render de UI só quando o valor exibido muda.
2. **Profundidade** — histórico persistido, custo estimado, alertas, multi-conta, analytics com previsão de trend.

### Non-goals (v1)

- Windows/Linux/iOS (a separação core/providers facilita port futuro, mas não é alvo)
- Sync em nuvem, times, dashboards web
- Renovar/gerenciar OAuth dos CLIs (lemos credenciais, nunca as renovamos)
- Interceptar tráfego dos CLIs (proxy local) — fora de escopo por risco e complexidade
- Widgets de tela, iOS intents, extensões

## 4. Arquitetura

App **single-process** (sem helpers/daemons), target **macOS 14+ (Sonoma)**, Swift 6 com strict concurrency. Estrutura em camadas com dependência unidirecional:

```
┌─────────────────────────────────────────────┐
│ UI (SwiftUI): MenuBarExtra, painel, alerts  │  ← só lê snapshots/projeções
├─────────────────────────────────────────────┤
│ SnapshotStore (@Observable, fonte de verdad)│
├──────────────┬───────────────┬──────────────┤
│ Scheduler    │ Transcript    │ AlertEngine  │
│ (actors)     │ Watcher       │              │
│              │ (FSEvents)    │              │
├──────────────┴───────────────┴──────────────┤
│ ProviderRegistry → [UsageProvider]          │
├─────────────────────────────────────────────┤
│ Persistence: SQLite (WAL) + PricingTable    │
└─────────────────────────────────────────────┘
```

### 4.1 Módulos (SPM targets)

- `TokenBarCore` — domínio, protocolos, scheduler, watcher, store de snapshots, alertas. Sem UIKit/SwiftUI, 100% testável.
- `TokenBarProviders` — um arquivo-módulo por provider (`ClaudeProvider.swift`, `CodexProvider.swift`, …).
- `TokenBarUI` — `MenuBarExtra`, painel, views de analytics (Swift Charts).
- `tokenbar` (executable) — wiring, injeção de dependências, ciclo de vida.

### 4.2 Concurrencia

- `ProviderEngine` (actor): coordena refresh por provider×conta, uma chamada de rede por vez por provider.
- `Scheduler` (actor): timers adaptativos com clock injetado (`any Clock<Duration>`), jitter ±10%, backoff exponencial em erro (×2, teto 30 min), pausa total em sleep (`NSWorkspace.willSleepNotification`) e refresh imediato no wake.
- `TranscriptWatcher`: `FSEventStream` → `AsyncStream<PathEvent>` → actor que debounces (3 s) e dispara ingest incremental.
- SnapshotStore: `@MainActor @Observable`; mutações publicam `version` incremental.

## 5. Protocolo de provider (ponto de extensão)

```swift
public protocol UsageProvider: Sendable {
    var id: ProviderID { get }                       // .claude, .codex, .gemini, .zai, .cursor, .openrouter...
    var capabilities: ProviderCapabilities { get }   // .apiUsage, .localIngest, .credits, .multiAccount
    func discoverAccounts() async -> [AccountRef]    // lê credential files/Keychain/env (read-only)
    func fetchUsage(_ account: AccountRef) async throws -> UsageSnapshot
    func ingestLocal(_ account: AccountRef, from offset: IngestCursor) async throws -> IngestBatch  // opcional
}
```

Regras invioláveis para todo provider:

1. **Read-only em credenciais.** Nunca escrever, mover ou renovar token dos CLIs. O CLI dono renova; nós lemos o estado atual.
2. **Degradação graciosa.** Sem token OAuth → *modo local*: tokens contados dos arquivos de sessão, janelas/limites marcados como desconhecidos (`usedFraction: nil`), UI mostra "local".
3. **Timeout de rede 10 s**, 1 tentativa por ciclo (sem retry imediato; o backoff do scheduler cuida).
4. **Nada de credenciais em log, erro, fixture ou doc.** Erros de auth viram estado (`accountAuthState: .invalid`), nunca mensagem com token.

### 5.1 Matriz de fontes por provider

| Provider | Contas (descoberta) | Uso/limites (rede) | Local (ingest) | Fase |
|---|---|---|---|---|
| Claude Code | `~/.claude/.credentials.json` → fallback Keychain ("Claude Code-credentials") → `CLAUDE_CODE_OAUTH_TOKEN` env | API OAuth de uso (endpoint reverso, estilo CodexBar) | `~/.claude/projects/**/*.jsonl` | F1 |
| Codex/OpenAI | `~/.codex/auth.json` | endpoint de usage do backend ChatGPT (estilo CodexBar) | `~/.codex/sessions/**/*.jsonl` | F2 |
| Gemini CLI | `~/.gemini/oauth_creds.json` | sem API pública estável de quota → normalmente modo local | sessões em `~/.gemini/tmp/<hash>/chats/` (formato a confirmar na implementação — tarefa de descoberta da F2, com fixture sintética gerada a partir do schema real) | F2 |
| Z.ai (coding plan) | credential do CLI ZCode em `~/.zcode/` | endpoint de usage do plano (estilo CodexBar) | — | F5 |
| Cursor | `~/.cursor` (session token) | API não documentada do cursor.com | — | F5 |
| OpenRouter | key de `OPENROUTER_API_KEY` ou keyring (entrada manual na UI) | REST pública: créditos + atividade por key | — | F5 |
| Copilot | `~/.config/github-copilot/` | API GitHub | — | F5+ (não instalado na máquina-base) |

Endpoints não documentados ficam isolados em cada provider, com fixture-replay nos testes; se mudarem, só aquele módulo quebra, e a UI mostra `última atualização: há Xh` em vez de dado errado.

### 5.2 Modelos de domínio (núcleo)

```swift
public struct UsageSnapshot: Sendable, Equatable {
    public let provider: ProviderID
    public let account: AccountID
    public let windows: [UsageWindow]        // ex.: sessão 5h, semanal
    public let credits: CreditsInfo?         // providers com crédito/USD
    public let fetchedAt: Date
    public let source: DataSource            // .api | .localOnly
    public let authState: AuthState          // .ok | .missing | .invalid
}

public struct UsageWindow: Sendable, Equatable {
    public let kind: WindowKind              // .session | .weekly | .daily
    public let usedFraction: Double?         // nil = desconhecido
    public let resetsAt: Date?
    public let label: String
}

public struct UsageEvent: Sendable {          // linha de ingest local
    public let ts: Date
    public let provider: ProviderID, account: AccountID
    public let model: String?
    public let inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens: Int64
    public let costUSD: Decimal?             // estimado na ingest
    public let project: String?
}
```

## 6. Persistência (SQLite, WAL)

Via GRDB (SPM). Banco em `~/Library/Application Support/TokenBar/tokenbar.sqlite`.

```sql
CREATE TABLE usage_events (
  id INTEGER PRIMARY KEY, ts REAL NOT NULL,
  provider TEXT NOT NULL, account TEXT NOT NULL, model TEXT,
  input_tokens INT DEFAULT 0, output_tokens INT DEFAULT 0,
  cache_read_tokens INT DEFAULT 0, cache_write_tokens INT DEFAULT 0,
  cost_usd REAL, source TEXT NOT NULL, project TEXT
);
CREATE INDEX idx_events_ts ON usage_events(ts);
CREATE INDEX idx_events_provider_ts ON usage_events(provider, ts);

CREATE TABLE daily_agg (
  day TEXT NOT NULL, provider TEXT NOT NULL, account TEXT NOT NULL, model TEXT NOT NULL,
  input_tokens INT DEFAULT 0, output_tokens INT DEFAULT 0,
  cache_read_tokens INT DEFAULT 0, cache_write_tokens INT DEFAULT 0,
  cost_usd REAL DEFAULT 0, PRIMARY KEY (day, provider, account, model)
);

CREATE TABLE accounts (
  provider TEXT NOT NULL, account_id TEXT NOT NULL,
  label TEXT NOT NULL, kind TEXT NOT NULL,       -- oauth | apikey
  active INT NOT NULL DEFAULT 1,
  PRIMARY KEY (provider, account_id)
);

CREATE TABLE pricing (                            -- versionada por validade
  model TEXT NOT NULL, valid_from TEXT NOT NULL,
  input_per_mtok REAL, output_per_mtok REAL,
  cache_read_per_mtok REAL, cache_write_per_mtok REAL,
  PRIMARY KEY (model, valid_from)
);

CREATE TABLE alert_rules (
  id INTEGER PRIMARY KEY, provider TEXT NOT NULL, account TEXT NOT NULL,
  window_kind TEXT NOT NULL, threshold_pct INT NOT NULL,
  enabled INT NOT NULL DEFAULT 1, last_fired_at REAL
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

- Ingest incremental: transação por lote; `daily_agg` atualizada na mesma transação.
- Custo é **estimativa**: calculado na ingest com a `pricing` vigente e sempre exibido como "~".
- Tabela `pricing` vem de JSON embutido no bundle (facilita PR de contribuição) e pode ser sobrescrita pelo usuário.
  > **Emenda F3 (2026-09-07, Task 5):** o mecanismo de sobrescrita pelo usuário NÃO foi implementado — a tabela vigente é a embutida (`PricingTable.bundled()`). O custo é calculado NA INGEST com ela, não-retroativo por construção: a marca d'água (`hwm`) impede re-leitura de eventos já persistidos, então preços nunca são reaplicados ao histórico; modelo sem preço público → `cost_usd` NULL, nunca 0. Override por arquivo externo fica para fase futura.

## 7. Performance (orçamento verificável)

| Métrica | Orçamento | Como |
|---|---|---|
| CPU ociosa (após 2 min sem interação) | < 0,5% | timers adaptativos, sem polling cego; watcher por FSEvents (não scan de diretório) |
| RAM estado estacionário (phys_footprint) | ≤ 40 MB | sem webview; eventos agregados diariamente; painel fecha → views descartadas |
| Rede | 0 em sleep; ≤ 1 req/provider/ciclo | pausa em `willSleepNotification`; scheduler centraliza |
| Re-render do ícone | só quando string exibida muda | `MenuBarRenderer` compara string formatada antes de tocar no `statusItem` |
| Parsing de transcript | incremental, só bytes novos | cursor `(path, offset)` por arquivo persistido em `settings`; batch na mesma runloop do debounce |
| Ingest de 10k eventos sintéticos | < 1 s | teste automatizado |

Intervalos do scheduler (todos com jitter ±10%): menu aberto → 60 s; pressão ≥ 80% do limite → 30 s; ocioso → 5 min (rede) e evento-driven (local); erro → backoff ×2 até 30 min. Primeira execução ao acordar do sleep e ao abrir o menu (throttle: não antes de 10 s da última).

> Métrica de RAM medida por `phys_footprint` (vmmap), não rss: o rss infla com páginas compartilhadas de SwiftUI/AppKit (~66 MB no macOS 26) não atribuíveis ao app; footprint medido em F1: 14,8–15,5 MB (`docs/decisoes-f1.md`, D11).

## 8. UI

- **Item de menu bar**: modo texto configurável (ex.: `C62 X15 G40`, uma letra/sigla por provider com % do limite mais próximo de esgotar) ou ícone SF Symbols com cor por pressão (verde < 60%, amarelo 60–85%, vermelho > 85%). Pin de providers visíveis configurável.
- **Painel principal** (`MenuBarExtra` estilo `.window`): lista de providers×contas com barra de uso por janela (5h/semana), timer de reset (`reseta em 2h14m`), créditos quando houver, badge "local" para modo local, timestamp `última atualização`.
- **Detalhe por provider**: sparkline 7 dias, breakdown por modelo, janelas com fração usada.
- **Analytics**: Swift Charts; períodos 24h/7d/30d/custom; agrupamento por provider/modelo/conta; custo estimado; **export CSV/JSON**; **previsão**: regressão linear dos últimos 7 dias projetada sobre a janela semanal → "ritmo atual esgota a cota qui, 16h" (sempre rotulado estimativa).
- **Alertas**: default 50/75/90/95% por provider×conta×janela; notificação via `UNUserNotificationCenter`; dedupe por (regra, janela): não re-dispara até reset ou fração cair abaixo do threshold; opção de lembrete 5 min antes do reset. Todas configuráveis por regra na UI.
- **Multi-conta**: descoberta automática + entrada manual (API keys); troca de conta ativa por provider; toggle "ver agregado".
  > **Emenda F4 (2026-09-08, Task 4):** multi-conta entregue como MECANISMO (ruling F4-MULTIACCOUNT): tabela `accounts` (migration v2), formulário "+ Add account" (credencial read-only + data directory própria), toggle ativo/inativo e remoção — cursor/hwm POR CONTA e agregado pior-caso (`decisoes-f4.md`, Decisões 3–5). A troca efetiva de credencial ativa multi-provider fica para a F5 (Cursor/OpenRouter). O guard de overlap vive na UI e na camada de app; registro programático direto no registry (fora do contrato do app) aceita dirs sobrepostas — comportamento documentado (Red Team F4 caso 5).
  > **Emenda F4 (paridade do painel — §8 "Painel principal", "Detalhe por provider" e "previsão" do Analytics):** o painel `.window` cumpre esta seção por inteiro com os dados da F2/F3: abas por provider com logos AUTORAIS simplificados (trademark dos donos — disclaimer no README), barras de janela com countdown de reset ("Renews in 6d 16h"; reset passado → "Renewed", nunca negativo), custos hoje/30d, série diária 30d dentro do painel (o sparkline do "Detalhe por provider", como chart de barras 30d sobre `daily_agg`) e a previsão antecipada como pacing (`PacingEngine` — regressão sobre agregados, rotulada "estimate — not a guarantee"; sem base → linha AUSENTE). Breakdown por modelo permanece na aba Analytics (F3); alertas notificáveis deslizam para a F5 (ruling F4-SCOPE).
- **Sistema**: launch at login (`SMAppService`), onboarding de 1ª execução explicando permissões (Keychain do Claude gera prompt do sistema — documentado na UI e no README).

## 9. Segurança e privacidade

- Credenciais: apenas leitura runtime dos arquivos dos CLIs / Keychain / env. Nenhuma credencial é copiada, logada, persistida no banco, ou aparece em fixtures/tests/docs (fixtures são sintéticas).
- Telemetria: **nenhuma**. Tudo local.
- Export respeita escopo de uso (tokens/custos), nunca credenciais.
- Keychain do Claude: leitura exige aprovação do usuário no prompt do macOS; sem aprovação → modo local.

## 10. Testes

- `swift test` (roda só com CLT):
  - Parsers de JSONL com **fixtures sintéticas** geradas por `tools/genfixtures/` (nunca transcripts reais).
  - Scheduler com clock injetado: backoff, jitter bounds, sleep/wake, throttle de menu.
  - Custo: matriz de casos sobre `pricing` (modelo ausente → custo `nil`, nunca chute).
  - AlertEngine: thresholds, dedupe, reset.
  - Performance smoke: ingest 10k eventos < 1 s; 10k snapshots → render gate não marca versão se string igual.
  - Provider: fixture-replay de respostas HTTP (URLSession stub) por provider.
- QA manual checklist (menu bar, painel, onboarding, keychain prompt) documentado em `docs/qa-manual.md`.

## 11. Build e distribuição (sem Xcode local)

- Toolchain local: CLT Swift 6.3.2 (validado). `swift build` + `swift test`.
- Bundle `.app`: script `scripts/make-app.sh` monta `TokenBar.app` (`Contents/MacOS/tokenbar`, `Info.plist` com `LSUIElement=true`, ícone `.icns` via `sips`+`iconutil` — sem `actool`), assinatura **ad-hoc** (`codesign --sign -`).
- Ícones em runtime via SF Symbols (nada de asset catalog compilado).
- CI: GitHub Actions `macos-latest` (runner tem Xcode completo — a restrição "sem Xcode" é só local) roda `swift test` em PR e builda artefato `.app.zip` na tag.
- Release v1: anexo de GitHub Release + instruções de Gatekeeper (clique direito → abrir). Fase 2: Developer ID + notarização + Sparkle.
